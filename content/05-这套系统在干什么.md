0. 先搞懂：这套系统在干什么
0.1 一句话
你在微信/网页看到好文章 → 存进 Notion → 勾一个复选框 → 10 分钟内它自动出现在你自己的网站上。

全程不用碰代码、不用传图片、不用点「发布」。

0.2 数据是怎么流的

 你的手机/电脑                     云端（自动）                        你的网站
┌──────────────┐            ┌──────────────────────┐          ┌──────────────────┐
│              │            │                      │          │                  │
│  微信读好文  │            │  ① Cloudflare Worker │          │  ④ VitePress     │
│      ↓       │            │     「搬运工」        │          │     静态站        │
│  Notion 剪藏 │──勾选────→ │     每 10 分钟巡查    │          │     35+ 篇文章   │
│      ↓       │  「已整理」│     读正文 + 下图片   │          │                  │
│  勾选「已整理」│            │           ↓          │          │                  │
│              │            │  ② GitHub 仓库        │─────────→│  ⑤ Cloudflare   │
└──────────────┘            │     kb-articles      │  ③ Actions│     托管上线     │
                            │     md + 配图         │  自动构建 │                  │
                            └──────────────────────┘          └──────────────────┘
                                        ↓
                                 ⑥ 回写 Notion：
                                    取消勾选 + 填 GitHub 链接
逐段白话解释：

环节	谁在做	做了什么
① 剪藏	你	用 Notion 剪藏插件把文章存进数据库，勾上「已整理」
② 搬运	Cloudflare Worker（定时）	每 10 分钟扫一次「已整理=true」的条目，把正文转成 Markdown、把图片下载下来
③ 入库	Worker	把 md 和图片提交到 GitHub 仓库 evener920/kb-articles
④ 构建	GitHub Actions	仓库一有提交就自动跑 npm run build，生成静态网站
⑤ 上线	Cloudflare	构建产物部署到 articles.201573.xyz
⑥ 回写	Worker	归档成功后自动取消 Notion 里的勾选，并把 GitHub 链接填回去（避免重复搬运）
0.3 名词表（小白必看）
名词	是什么	打个比方
Notion	在线笔记/数据库	你的「内容仓库」，负责收集
GitHub	代码托管平台	你的「档案室」，存 Markdown 和图片，有版本历史
Markdown（.md）	纯文本写作格式	比 Word 简单，一行 # 就是标题
frontmatter	md 文件开头 --- 包起来的元信息	文章的「身份证」：标题、分类、标签、日期
Cloudflare Worker	云上运行的一段 JS（无需服务器）	你的「自动搬运工」，24 小时值班
cron	定时触发器	闹钟，*/10 * * * * = 每 10 分钟响一次
VitePress	把 md 变成漂亮网站的生成器	「印刷厂」
GitHub Actions	GitHub 自带的自动化流水线	「流水线工人」，仓库一变就开工
slug	URL 里那段英文短名	中文标题不能直接进网址，要翻译成安全字符
token / secret	访问密码	相当于钥匙，绝不能写进代码里公开
KV	Worker 用的小型键值存储	一个小本子，记「这篇失败过几次」
0.4 为什么这么设计（对比）
方案	优点	缺点	结论
直接用 Notion 公开页	零搭建	丑、慢、不能搜索、域名不是自己的	❌
自己买服务器 + WordPress	功能全	花钱、要运维、会被攻击	❌
Notion + GitHub + VitePress（本方案）	全免费、全自动、内容自有 md、可搜索、极快	需要一次性搭建	✅
纯前端索引（不落 md）	简单	图片会失效、不能版本管理	❌
关键决策：内容必须以 Markdown 落到 GitHub。 这样即使哪天 Notion 倒闭、Cloudflare 收费，你的文章还在自己手里。

1.2 本地要装的工具
打开「终端」（Mac：Command+空格 搜 Terminal），逐条执行：


# 1) 检查 Node.js（要求 ≥ 20，本项目用 22）
node -v
# 没装 → 去 nodejs.org 下载 LTS 版安装

# 2) 检查 Git

1.3 验收点
node -v 输出 v22.x.x

2. 第 1 步：搭 Notion 数据库
2.1 建数据库并配字段
在 Notion 新建一个 Database（数据库），比如叫「文章数据库」。字段必须按名字和类型建好：

字段名	类型（必须一致）	作用	谁在写
Name	Title	文章标题	你（剪藏时自动）
已整理	Checkbox（复选框）	同步开关：勾上 = 请搬运	你勾，Worker 完成后取消
分类	Select	归类（如「AI」「读书」）	你
标签	Multi-select	多标签	你
作者	Select	作者	你
发布时间	Date	排序用	你
文章链接	URL	原文出处	你
GitHub链接	URL	归档后的 md 地址	Worker 自动回写
⚠️ 踩坑 #1（真实发生过）：已整理 是 Checkbox（复选框），不是 Select（下拉）。

这两种在 Notion API 里的过滤写法完全不同：

复选框：{ property: "已整理", checkbox: { equals: true } }
下拉框：{ property: "已整理", select: { equals: "已整理" } }
写错会直接报 400，一条都查不出来。

2.2 建 Integration（给程序一把钥匙）
打开 https://www.notion.so/my-integrations
点 New integration → 名字随便（本项目叫 smartclip）→ 选你的 workspace
Capabilities 勾上 Read content / Update content / Insert content
提交后复制 Internal Integration Secret，形如 ntn_xxxx... ← 这就是 NOTION_TOKEN
2.3 把数据库共享给 Integration（最容易漏的一步）
光建 Integration 没用，必须在数据库页面授权：

打开你的数据库页面
右上角 ⋯ → Connections → 找到刚建的 integration → 点 Connect
⚠️ 不做这一步，Worker 读到的永远是空库（返回 0 条，不报错，最难排查）。

2.4 拿到数据库 ID
看数据库页面的网址：


https://www.notion.so/6bafeb00ed7283ac9294019f70c1557a?v=xxxx
                      └────────── 这 32 位就是数据库 ID ──────────┘
本项目用的是：6bafeb00ed7283ac9294019f70c1557a

⚠️ 踩坑 #2：Notion API 对 ID 格式敏感。URL 里是无连字符的 32 位，

但打 /v1/databases/{id}/query 时必须补成 8-4-4-4-12 的 UUID 格式：

`

6bafeb00-ed72-83ac-9294-019f70c1557a

`

否则返回 400 invalid_request_url。代码里用 uuidOf() 自动补。

2.5 验收点

# 用你的 token 试查一下（Mac 终端）
curl -X POST "https://api.notion.com/v1/databases/6bafeb00-ed72-83ac-9294-019f70c1557a/query" \
  -H "Authorization: Bearer ntn_你的token" \
  -H "Notion-Version: 2022-06-28" \
  -H "Content-Type: application/json" \
  -d '{"page_size":3}'
返回里有 "results" 且有内容 = 成功。返回 object: "error" 就是 ID 或共享没配好。

3. 第 2 步：建 GitHub 仓库与令牌
3.1 建仓库
GitHub 右上角 + → New repository

名字：kb-articles
选 Public（公开仓库的 Actions 免费额度更足，且方便以后给别人看）
勾选 Add a README
3.2 建 Personal Access Token（给 Worker 写文件的权限）
GitHub 头像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
Repository access：选 Only select repositories → 选 kb-articles
Permissions → Contents: Read and write（必须，写入 md 和图片靠它）
生成，复制 github_pat_xxx... ← 这就是 GITHUB_TOKEN
保存好，只显示一次。

3.3 记下三个值
变量	本项目的值	你的值
GITHUB_OWNER	evener920	你的 GitHub 用户名
GITHUB_REPO	kb-articles	仓库名
GITHUB_BRANCH	main	默认分支名
3.4 验收点

curl -H "Authorization: Bearer 你的GITHUB_TOKEN" \
  https://api.github.com/repos/你的用户名/kb-articles
返回里有 "full_name": "xxx/kb-articles" = 通了。

4. 第 3 步：写 Worker（搬运工）
这是整套系统的心脏。它是一段跑在 Cloudflare 上的 JS，24 小时值班。

4.1 项目结构

notion-github-sync/
├── wrangler.toml      # 配置：域名、定时任务、KV、限额
├── deploy.sh          # 一键部署脚本（自动引导填 3 个密钥）
└── src/
    ├── index.js       # 主编排：端点 + 批量同步 + 失败防护
    ├── notion.js      # 读 Notion：查询 + 正文 blocks → Markdown
    └── github.js      # 写 GitHub：提交 md 和图片
4.2 wrangler.toml 逐段解释

name = "notion-github-sync"
main = "src/index.js"
compatibility_date = "2024-12-01"

# ⭐ 自定义域：必须用自定义域，不能用 workers.dev
#   （原因见踩坑 #3：Cloudflare 的 bot 防护会拦掉 Notion 的请求）
# ⚠ routes 必须写在所有 [xxx] 表头之前，否则会被解析进上一个表
routes = [
  { pattern = "git.201573.xyz", custom_domain = true }
]

# 每 10 分钟扫一次「已整理 = true」的条目
[triggers]
crons = ["*/10 * * * *"]

# KV：存 webhook 握手令牌 + 失败计数
[[kv_namespaces]]
binding = "KV"
id = "fb98bff2e0764127b6d6754cb7f9f947"

[vars]
NOTION_DS_ID = "6bafeb00ed7283ac9294019f70c1557a"
NOTION_DB_ID = "6bafeb00ed7283ac9294019f70c1557a"
GITHUB_OWNER = "evener920"
GITHUB_REPO  = "kb-articles"
GITHUB_BRANCH = "main"

# ⚠ 关键！放宽子请求上限（见踩坑 #4）
[limits]
subrequests = 200

[observability]
enabled = true
